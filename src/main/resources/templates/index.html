Continuous Delivery Engineering

The End-to-End DevOps Pipeline

A production-grade, 10-stage delivery workflow driven by Jenkins Pipeline as Code, enforcing strict quality gates, non-root container packaging, and self-healing rollback.

Stage 1 Git & GitHub

Source Control & GitFlow

Strict branching with main (production releases), develop (integration), and dedicated feature/* branches merged via audited Pull Requests.

🛡️ PR Peer Review & SCM Polling
Stage 2 Jenkins 2.568.1

Pipeline as Code

Version-controlled declarative Jenkinsfile executed on Jenkins port 8080. Parameterized for environment selection, branch targets, and port safety.

⚡ Automated Pipeline Orchestration
Stage 3 Maven 3.9 + JUnit 5

Build & Unit Tests

Runs mvn clean test across 30 unit and slice test cases (PlanService, UserService, RecommendationEngine, PlanController) against in-memory H2.

🛑 Fatal Gate: 30/30 Must Pass
Stage 4 Selenium WebDriver

UI Testing Quality Gate

Executes 5 end-to-end browser user journeys in headless Chrome with Page Object Model. Automatically captures screenshots on failure and blocks deployment.

🛑 Quality Gate: 5/5 UI Journeys
Stage 5 Maven WAR Plugin

Artifact Packaging

Compiles reproducible Web Application Archive (target/*.war) with embedded Spring Boot launcher and metadata for standalone Tomcat deployment.

📦 Binary Artifact Archiving
Stage 6 Apache Tomcat 10.1

Standalone Server Deploy

Copies WAR to webapps/mpr-platform.war on port 8084. Executes health-check.ps1 polling /actuator/health until UP is confirmed.

🔍 Health Probing: Port 8084
Stage 7 Docker Engine

Container Image Packaging

Builds image using multi-stage Dockerfile based on tomcat:10.1-jdk17. Enforces non-root security with unprivileged USER 1001 (appuser).

🔒 Hardened Non-Root Image
Stage 8 Docker Desktop

Container Deployment

Runs mpr-platform-container mapping host port 8085 to container 8080. Protects foreign containers (driving-school-container) and avoids reserved ports.

🌐 Continuous Deploy: Port 8085
Stage 9 Ansible Core 2.21

Configuration Management

Modular Ansible roles via container runner (mpr-ansible-runner:latest) with port policy assertions and verified second-run idempotency (0 container modifications).

⚙️ Idempotent State Management
Stage 10 Ansible & PowerShell

Reliability & Self-Healing

Iterative health probing with automated rollback. If health probe fails, scripts immediately redeploy previous known-good tag from deployment-state.json.

🔄 Self-Healing Rollback Recovery

🛡️ Pipeline Quality Gate & Safety Guarantee

The pipeline enforces a Fail-Fast Architecture: if any unit test or Selenium E2E journey fails, downstream WAR packaging, server deployment, and Docker container publishing are instantly aborted (demonstrated in Jenkins Build #12). Production deployments enforce strict port safety assertions (rejecting reserved ports 8072, 8081, 8082), container isolation protecting unrelated services, and audited rollback metadata in deployment-state.json.

Quality Assurance

Verified Reliability Practices

Demonstrable engineering safeguards ensuring system stability, repeatable automation, and defense-in-depth security.

Test Pyramid Verification

Full suite comprises 30 backend unit and slice tests plus 5 Selenium headless Chrome end-to-end user journeys validating RBAC, catalogue filters, and status transitions.

Port 8085 Policy Enforced

Strict Port Isolation

Tomcat binds to 8084 and Docker maps host port 8085 to container 8080. Assertions in Jenkins and Ansible halt execution if reserved ports (8072, 8081, 8082) are touched.

UID 1001 Hardened

Non-Root Execution

Container executes strictly under unprivileged user 1001 (appuser), mitigating container breakout risks and securing host infrastructure.

100% Isolated Protected

Foreign Container Safety

Container lifecycle scripts and playbooks target strictly mpr-platform-container. Unrelated running containers (e.g. driving-school-container) are never touched.

ok=30 changed=5 Idempotent

Ansible Idempotency

Demonstrated on repeated runs: existing directories, configurations, and running containers register skipping, producing 0 redundant container restarts.

Auto Recovery Verified

Self-Healing Rollback

Tested via non-destructive simulation harness: failed container health automatically triggers rollback to previous known-good tag from deployment-state.json, restoring UP status.
